# ADR-019: Владение данными в трёх сервисах

Статус: принято. Дата: 2026-09-20. Версия архитектуры: 2.0.0.
## Контекст
Один экземпляр PostgreSQL обслуживает все сервисы. Требуется исключить скрытые связи через общие таблицы.

## Решение
Схема на сервис: `core`, `reminders`, `bot`. У каждой схемы отдельная роль-владелец (`*_migrator`)
и роль приложения (`*_app`). Сервис обращается только к своей схеме.
Межсервисных внешних ключей нет. Связь между схемами — только по значениям идентификаторов.

## Основания
Логическое разделение даёт независимость миграций и контроль доступа без второго экземпляра СУБД,
что соответствует ограничению «минимум инфраструктуры».

## Недостатки
Общий экземпляр остаётся единой точкой отказа и общим ресурсом по соединениям и вводу-выводу.

## Последствия
- `reminders_app` не имеет прав на схемы `core` и `bot`.
- Роль приложения не может изменять таблицу истории миграций (исправление дефекта прежней схемы).
- Проверка владения вынесена в тест (TestSchemaOwnershipHasNoForeignReferences).

## Условия пересмотра
Рост нагрузки, при котором сервисам требуются независимые параметры СУБД, — разделение на экземпляры.
