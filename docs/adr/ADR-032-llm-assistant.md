# ADR-032: Языковой ассистент ввода данных (GigaChat)

Статус: принято. Дата: 2026-09-26. Версия архитектуры: 2.0.0.

## Контекст
Самое дорогое место пользовательского пути — первичный ввод: пока в реестре нет
документов, продукт бесполезен, а владелец заведения вносит 8–15 карточек вручную
и отмечает признаки бизнеса, не зная, какие из них важны. Напоминания, статусы,
роли и экспорт работают без языковой модели и в ней не нуждаются.

Кейс трека прямо предупреждает: технология выбирается под задачу, а не наоборот.

## Решение
Подключается GigaChat API в двух сценариях извлечения и классификации:

- **FR-21** `POST /organizations/{id}/documents/draft` — извлечение реквизитов
  документа из свободного текста в черновик формы;
- **FR-22** `POST /profile-match` — сопоставление свободного описания бизнеса
  с кодами справочника (вид деятельности и признаки).

Архитектурные решения:

1. Четвёртый микросервис не создаётся: ассистент — исходящий адаптер core-service
   (`internal/adapters/gigachat`) за портом `ports.DraftAssistant`, как `botgrpc`
   и `remindersgrpc`. Сценарии в `internal/app` не знают о HTTP и о модели.
2. Модель отвечает только структурой: `response_format: json_schema` со `strict: true`,
   `function_call: "none"`, `temperature: 0`. Коды типов, категорий и признаков
   передаются закрытым перечнем `enum`, собранным из справочника.
3. Ответ модели не принимается на веру: сервер повторно проверяет коды по справочнику,
   приводит даты к `YYYY-MM-DD` и отбрасывает значения вне диапазона 1990 … +30 лет,
   обнуляет перевёрнутые пары дат, режет длины по границам OpenAPI, ограничивает
   `confidence` отрезком [0, 1].
4. Ассистент не входит в критический путь: он не участвует в напоминаниях, статусах,
   плане и доставке событий. Отказ, тайм-аут и исчерпание бюджета дают 503
   `DEPENDENCY_UNAVAILABLE`, а форма остаётся доступной для ручного ввода.
5. Ничего не сохраняется автоматически: обе операции возвращают черновик, который
   подтверждает пользователь обычными `POST /documents` и созданием организации.
6. Функция выключается пустым `CORE_GIGACHAT_AUTH_KEY`; состояние объявляется полем
   `assistant_enabled` в `GET /me`, и интерфейс скрывает соответствующие элементы.

## Границы применения
Языковая модель не используется для: юридических консультаций и ответов о требованиях
законодательства; определения сроков действия документов; генерации шагов продления
(они берутся из справочника с пометкой `data_status`); свободного диалога в боте.

## Приватность и безопасность
Наружу уходит только текст, который пользователь ввёл сам, и коды справочника.
Не передаются: идентификаторы пользователя и организации, `max_user_id`, имена
участников, токены сессий, содержимое других документов. В журнал пишется длина
текста, операция и исход — не содержимое. Ключ авторизации хранится только в `.env`
(поддерживается суффикс `_FILE`), в репозиторий и в бандл мини-приложения не попадает:
браузер к GigaChat не обращается. TLS-проверка не отключается никогда; доверие к
доменам Сбера обеспечивается бандлом НУЦ Минцифры, который собирается в образ core.

## Расходы
Один разбор — сотни токенов. Ограничители: частота на аккаунт
(`CORE_RATE_ASSISTANT_PER_MIN`), суточный бюджет токенов
(`CORE_GIGACHAT_DAILY_TOKEN_BUDGET`) с отказом по исчерпании, метрики
`vovremya_assistant_requests_total` и `vovremya_assistant_tokens_total`.

## Недостатки
Качество разбора зависит от внешнего сервиса и формулировок пользователя; при
недоступности GigaChat сценарии ввода возвращаются к ручному заполнению.
Затраты на запросы растут линейно с числом разборов.

## Последствия
Контракт публичного API повышен до 1.2.0: две операции и поле `assistant_enabled`.
Образ core-service получает бандл НУЦ Минцифры. Тесты используют управляемый двойник
`gigachattest`; реальных обращений к GigaChat в тестах нет.
