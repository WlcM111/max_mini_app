# ADR-023: Чтение плана для публичного API

Статус: принято. Дата: 2026-09-20. Версия архитектуры: 2.0.0.
## Контекст
Поля `next_reminder_at` в реестре и карточке документа принадлежат плану напоминаний,
который теперь хранится в reminders-service.

## Рассматриваемые варианты
1. Обратная проекция плана в core. Ещё один поток событий и дублирование состояния.
2. Синхронный gRPC-запрос core → reminders при чтении списка и карточки.

## Решение
Вариант 2: `ReminderQueryService/GetNextReminders` (пакетно, до 200 документов).
При недоступности reminders core возвращает документы без значения `next_reminder_at`
и признак состояния плана; отказ reminders не блокирует чтение и изменение документов.

## Основания
Один дополнительный индексированный запрос дешевле второго потока событий и обратной проекции.

## Недостатки
Появляется синхронная зависимость на пути чтения; при отказе reminders интерфейс теряет одно поле.

## Последствия
OpenAPI дополнен полем состояния плана; `next_reminder_at` допускает null и не выдаётся за гарантированно актуальное.

## Условия пересмотра
Рост задержки на пути чтения свыше бюджета — переход к обратной проекции.
