# ADR-025: Чистая слоистая архитектура внутри сервисов

Статус: принято. Дата: 2026-09-20. Версия архитектуры: 2.0.0.
## Контекст
В прежней структуре core предметные контексты были сложены по техническим слоям,
а в bot разбор формата MAX находился в домене.

## Решение
Каждый сервис использует слои domain → application → ports ← adapters с направлением зависимостей внутрь.
core-service дополнительно делится на модули по предметным контекстам; модули не импортируют друг друга
и взаимодействуют через порты, объявленные потребителем.
Разбор webhook MAX и формирование запросов MAX API находятся в адаптерах bot-service.

## Основания
Границы модулей совпадают с возможными границами будущих сервисов, что делает выделение заменой реализации порта.

## Недостатки
Больше интерфейсов и связующего кода в composition root.

## Последствия
Правила проверяются архитектурным тестом (services/reminders/internal/archtest), который запрещает
импорт адаптеров из домена и сценариев, а также импорт сервисов из общего каркаса.

## Условия пересмотра
Не предусмотрен: правило распространяется на все три сервиса.
