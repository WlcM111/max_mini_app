# ADR-022: Локальные проекции core-данных в reminders-service

Статус: принято. Дата: 2026-09-20. Версия архитектуры: 2.0.0.
## Контекст
Для построения плана нужны дата окончания документа, отступы, часовой пояс организации,
настройки участников и идентификаторы получателей MAX.

## Рассматриваемые варианты
1. Синхронный запрос в core на каждом тике планировщика. Простая модель данных, но постоянная зависимость доступности и рост нагрузки на core.
2. Локальные проекции, обновляемые событиями.

## Решение
Вариант 2: reminders-service хранит собственные проекции организаций, участников, документов и отступов.
Источник истины остаётся в core; проекции версионируются полем `aggregate_version`.

## Основания
Планировщик работает без обращения к core, что исключает циклическую зависимость
и сохраняет работу напоминаний при недоступности core.

## Недостатки
Дублирование данных и возможное отставание проекции.

## Последствия
- События переносят полное состояние агрегата (event-carried state transfer), что упрощает восстановление.
- Сверка выполняется core по `GetIngestState`: при расхождении версии relay повторно отправляет снимок.
- Отправка по заведомо устаревшему состоянию запрещена: планировщик проверяет проекцию перед вызовом bot.

## Условия пересмотра
Рост объёма проекций до величины, сравнимой с core, — переход к запросам по требованию с кэшем.
