# ADR-013. Развёртывание Docker Compose

**Вопрос.** Как запускать систему локально, у проверяющих и на стенде?

**Требования.** Docker Compose; одна команда запуска; сборка ≤ 5 минут; Kubernetes запрещён без обоснования; честная оценка отказоустойчивости.

**Решение.** Один `compose.yaml` для всех окружений; различия — в переменных окружения. Сервисы: `postgres`, `core-migrate`, `bot-migrate` (одноразовые), `bot`, `core`, `edge`; профили `monitoring` (Prometheus), `test` (`postgres-test` в tmpfs), `loadtest` (k6). Сети: `edge` 10.77.1.0/24 (edge, core, bot) и `data` 10.77.2.0/24 `internal: true` (postgres, core, bot, миграции). Порядок старта — `depends_on` с `service_healthy` и `service_completed_successfully`. Ресурсные лимиты, healthcheck у каждого долгоживущего сервиса, `stop_grace_period: 30s`. Команда запуска: `docker compose up -d --build`.

**Основания.** Одна машина покрывает целевой профиль нагрузки; миграции отдельными контейнерами под ролью-владельцем схемы, а приложения работают ролью без DDL.

**Недостатки.** Отказ хоста = отказ системы (нет резервирования); обновление с кратким простоем (секунды на пересоздание контейнера).

**Последствия.** Резервное копирование `pg_dump` по расписанию хоста ([runbook](../operations/compose-and-runbook.md)).

**Проверка.** T-NFR-BUILD (`scripts/measure_build.sh`), T-NFR-RESTART.

**Условия пересмотра.** Требование доступности > 99,5 % — второй хост и управляемая БД.
