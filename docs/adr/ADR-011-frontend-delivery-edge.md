# ADR-011. Раздача frontend и edge

**Вопрос.** Как отдавать статику, публичный API и webhook по HTTPS?

**Требования.** URL мини-приложения только https (F-03); webhook только на 443 с доверенным сертификатом (F-44); без отдельного API Gateway; один origin (без CORS); CSP с `frame-ancestors`.

**Варианты.** A. Nginx + certbot — два механизма и cron обновления. B. Caddy 2 — автоматический ACME, reverse proxy, статика одним конфигом. C. Раздача статики из `core` — смешивает ответственность и усложняет кеширование.

**Решение.** B. Образ `edge` собирает frontend (Node 22) и копирует `dist` в Caddy 2.10. Маршруты: `/api/*` → `core:8080`, `POST /max/webhook` → `bot:8080`, прочее — SPA с `try_files … /index.html`. Заголовки: CSP (`script-src 'self' https://st.max.ru`, `frame-ancestors` из `EDGE_FRAME_ANCESTORS`), HSTS, `nosniff`, `Referrer-Policy: no-referrer`; `X-Request-Id` генерируется edge. Ограничение тела 256 KB. `/assets/*` кешируется год (имена с хешем), `index.html` — `no-cache`.

**Основания.** Один процесс решает TLS, статику и маршрутизацию; это не API Gateway (нет бизнес-логики, авторизации, агрегации).

**Недостатки.** Точный origin веб-клиента MAX для `frame-ancestors` не подтверждён (U-02); неверное значение ломает встраивание в веб-версии.

**Последствия.** MAX-03 в первый день проверяет встраивание во всех клиентах; значение меняется переменной окружения без пересборки.

**Проверка.** T-INT-EDGE: заголовки ответа; AC-MAX-01 на платформе web.

**Условия пересмотра.** CDN потребуется при аудитории > 100 000 одновременных пользователей (не в целевом профиле).
