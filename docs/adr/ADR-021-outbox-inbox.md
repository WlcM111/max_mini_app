# ADR-021: Транзакционный outbox в core и inbox в reminders

Статус: принято. Дата: 2026-09-20. Версия архитектуры: 2.0.0.
## Контекст
Требуется надёжная передача изменений без брокера сообщений, транспорт — gRPC.

## Решение
core-service ведёт таблицу `core.outbox_events` (событие пишется в транзакции изменения).
Relay выбирает записи пакетами с `FOR UPDATE SKIP LOCKED` и арендой, вызывает
`vovremya.reminders.v1.IngestService/ApplyEvents`, фиксирует результат по каждому событию.
reminders-service ведёт таблицу `reminders.inbox_events` с первичным ключом `event_id`:
повторная доставка распознаётся и не выполняет повторного бизнес-действия.

## Основания
Одна транзакция «изменение + событие» исключает потерю задания.
Журнал входящих событий даёт идемпотентность без изменения доменных таблиц.

## Недостатки
Две дополнительные таблицы и фоновый процесс; требуется очистка по сроку хранения.

## Последствия
- Ответ ApplyEvents содержит исход по каждому событию: applied, duplicate, stale, rejected.
- Таймаут после успешной обработки приводит к повторной доставке, которая распознаётся как duplicate.
- Застрявшие события обнаруживаются по возрасту записи outbox и метрике задержки.

## Условия пересмотра
Появление нескольких потребителей событий — переход к брокеру с сохранением outbox.
