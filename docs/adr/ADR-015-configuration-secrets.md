# ADR-015. Конфигурация и секреты

**Вопрос.** Как передавать настройки и секреты, чтобы локальный запуск был одной командой, а в репозитории не было рабочих секретов?

**Требования.** Кейс запрещает рабочие токены в репозитории; `.env.example` без секретов; одна команда запуска.

**Решение.** Все настройки — переменные окружения, словарь — [configuration.md](../operations/configuration.md). `compose.yaml` содержит значения по умолчанию только для локального режима с префиксом `devonly` (пароли БД, секрет webhook, dev-токен имитации). Сервисы при `APP_ENV=prod` завершаются с ошибкой, если любое секретное значение начинается с `devonly` или равно dev-ключу `e45f5316…d663`. Для prod `.env` создаёт `scripts/generate_prod_env.py` (права 600, в `.gitignore`). Каждая секретная переменная `X` может быть задана файлом через `X_FILE`.

**Основания.** Проверяющие запускают систему без подготовки; prod-запуск с dev-секретами невозможен.

**Недостатки.** Переменные окружения видны через `docker inspect` пользователю хоста — доступ к серверу имеют только два разработчика.

**Проверка.** T-SEC-06: запуск `APP_ENV=prod` с dev-паролем завершается кодом 1 и сообщением `insecure default secret`.

**Условия пересмотра.** Появление менеджера секретов на стенде.
