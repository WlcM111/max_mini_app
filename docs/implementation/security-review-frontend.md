# Обзор безопасности клиентского приложения

Версия 1.0.0 · 24.09.2026. Нормативные источники: `docs/architecture/security.md`,
`docs/frontend/frontend-architecture.md` §13, ADR-007, ADR-009.

## 1. Секреты и конфигурация

| Проверка | Результат |
|---|---|
| Серверные секреты в бандле | отсутствуют: в клиент попадают только `VITE_API_BASE_URL`, `VITE_APP_VERSION`, флаг имитации |
| Токен бота MAX | в клиенте не используется; проверку `initData` выполняет core-service |
| Пароли PostgreSQL, межсервисные адреса | в клиенте отсутствуют |
| Dev-токен имитации | только при `VITE_MOCK_BRIDGE=true`; сборка образа падает, если строка `devonly` попала в prod-бандл (`deploy/edge/Dockerfile`) |
| Имитация Bridge в prod | подключается динамическим `import()` под флагом; в prod-сборке чанк отсутствует |

Проверено фактически: `grep -r "devonly" frontend/dist` после `npm run build` при
`VITE_MOCK_BRIDGE=false` — совпадений нет.

## 2. Авторизация и данные пользователя

- Личность подтверждает сервер по подписанной строке `initData` (ADR-007); клиент не формирует
  и не подменяет идентификатор пользователя.
- Токен сессии хранится в памяти и `sessionStorage` (ADR-009), cookie не используются,
  CSRF неприменим.
- Ответ 401 приводит к одному обновлению сессии и повтору запроса; повторный отказ —
  экран перезапуска, состояние очищается.
- Доступ к чужим данным невозможен со стороны клиента: проверки роли и владения выполняет
  core-service, интерфейс лишь скрывает недоступные действия. Подтверждено T-INT-16:
  наблюдатель получает `FORBIDDEN` на изменение документа.
- Строка `initData` не логируется и не отправляется в телеметрию (проверяется сценарием
  `frontend/e2e/launch.spec.ts`).

## 3. Недоверенные данные и XSS

- `dangerouslySetInnerHTML` запрещён правилом ESLint; в коде не встречается.
- Значения сервера и MAX выводятся как текстовые узлы React (экранирование по умолчанию).
- Внешние ссылки открываются только после проверки `isSafeExternalUrl` — допускается
  исключительно схема `https:`; `javascript:` и относительные адреса отклоняются (тест в `bridge.test.ts`).
- Результат сканера QR приводится к безопасному виду: ссылка (только `https://`, ≤ 1024)
  или номер (≤ 100 символов), иначе показывается сообщение.

## 4. Транспорт и CSP

- Все запросы идут на публичный API того же источника (`/api/v1`), внутренние gRPC-адреса
  браузеру недоступны.
- Стили и скрипты — внешние файлы, inline-кода нет: совместимо с политикой
  `script-src 'self' https://st.max.ru` из `deploy/edge/Caddyfile`.
- HTTPS и заголовки безопасности обеспечивает edge; приложение не ослабляет их.

## 5. Хранилища браузера

| Ключ | Хранилище | Содержимое | Обоснование |
|---|---|---|---|
| `vovremya.session` | sessionStorage | токен и срок действия, имя пользователя | переживает перезагрузку страницы, исчезает с вкладкой (ADR-009) |
| `vovremya.lastOrg` | localStorage | UUID последней организации | удобство запуска; не является чувствительными данными |
| `vovremya.onboarding` | sessionStorage | черновик онбординга | не теряется при перезагрузке во время заполнения |
| `vovremya.renewal.<documentId>` | localStorage | номера отмеченных шагов продления | личная пометка пользователя, предметных данных не содержит; потеря безопасна, шаги приходят из справочника |

Чувствительные данные документов в браузере не кэшируются: источник истины — сервер.

## 6. Аудит зависимостей

Проверка 26.09.2026 командой `npm audit` на зафиксированном `package-lock.json`:

| Область | Уязвимостей |
|---|---|
| Все зависимости, включая инструменты разработки | 2 (critical 1, high 0, moderate 1, low 0) |
| Только production-зависимости (`npm audit --omit=dev`) | 0 |

Найденное относится к `vitest` и `@vitest/mocker` — запускателю тестов. Эти пакеты
не входят в production-сборку и не выполняются на стенде; условие эксплуатации —
запущенный UI-сервер Vitest, который в проекте не используется. Версии намеренно
не поднимались: `package-lock.json` зафиксирован и проверен тестами и сборкой,
обновление запускателя перед сдачей несёт больший риск, чем устраняет.

## 7. Остаточные риски

| Риск | Оценка | Мера |
|---|---|---|
| Компрометация устройства пользователя | вне контроля приложения | короткий срок сессии (12 ч), выход и удаление данных в интерфейсе |
| Подмена ответа API посредником | низкая при HTTPS | обязательный HTTPS на стенде MAX; смешанного контента нет |
| Утечка ссылки приглашения | средняя | ссылка одноразовая и живёт 72 часа, отзывается владельцем |
| Ссылка экспорта календаря | низкая | одноразовый токен, 10 минут, не более 3 скачиваний |
