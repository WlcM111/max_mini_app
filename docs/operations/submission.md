## 3. Первый служебный слайд (шаблон)

| Поле | Значение |
|---|---|
| Мини-приложение в MAX | `https://max.ru/<ник бота>` — нажать «Открыть» |
| Git и commit | `<ссылка на репозиторий>`, тег `v1.0.0`, `<commit hash>` |
| Адрес API | `https://<домен>/api/v1` (OpenAPI: `openapi.yaml`) |
| Тестовые учётные записи | `reviewer_editor` — `Authorization: Bearer vvs_…` (роль editor); `reviewer_viewer` — `Bearer vvs_…` (роль viewer); вход в мини-приложение — любой аккаунт MAX, данные создаются при первом запуске |
| Значения окружения для запуска | для локальной проверки не требуются: `docker compose up -d --build` работает со значениями по умолчанию; рабочий токен бота нужен только стенду и не передаётся |
| Порядок сценария | 1) открыть бота → «Открыть»; 2) создать организацию «Общепит», отметить признаки; 3) принять предложенные документы, указать даты; 4) увидеть статусы на дашборде; 5) в карточке документа нажать «Продлить»; 6) в «Настройках» поставить время напоминаний через 3 минуты и дождаться сообщения бота; 7) нажать кнопку в сообщении — откроется карточка |

## 4. Чек-лист перед отправкой (28.09, REL-01)

| № | Проверка | Критерий |
|---|---|---|
| 1 | Все AC и AC-MAX пройдены на стенде | протокол в `docs/testing/acceptance.md` заполнен |
| 2 | `scripts/measure_build.sh` на чистой машине | `build_seconds` ≤ 300 |
| 3 | `scripts/run_data_api_checks.py` с токенами проверяющих против стенда | все PASS |
| 4 | В репозитории нет секретов | `git grep -nE "vvs_[A-Za-z0-9_-]{43}|[0-9]{8,}:[A-Za-z0-9_-]{30,}"` пусто; `.env` отсутствует |
| 5 | `DATA-API.yaml.base_url` = адрес стенда | совпадает со слайдом |
| 6 | README соответствует таблице раздела 2 | 15 разделов |
| 7 | Тег `v1.0.0` поставлен, hash записан на слайд | `git rev-parse v1.0.0` |
| 8 | После дедлайна изменений нет | ветка защищена от push |

После окончания проверки: `review-token revoke` для обоих логинов.
