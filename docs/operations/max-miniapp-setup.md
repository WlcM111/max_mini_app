# Подключение и проверка Mini App внутри MAX

Версия 1.0.0 · 24.09.2026. Документ описывает действия, которые выполняются вне среды
разработки: они требуют токена бота и публичного домена. Задачи MAX-03 и MAX-04.

## 1. Что нужно заранее

| Условие | Где берётся | Проверка готовности |
|---|---|---|
| Токен бота MAX | кабинет партнёра (business.max.ru → Чат-боты), выдают организаторы | `curl -fsS -H "Authorization: <токен>" https://botapi.max.ru/me` |
| Публичный домен с HTTPS | хостинг команды | сертификат выпускается Caddy автоматически |
| URL мини-приложения | настройки бота в кабинете MAX | ≤ 1024 символов, только `https://`, без пробелов (F-03) |
| Собранный стенд | `docker compose up -d --build` | `docker compose ps` — все `healthy` |

## 2. Настройка стенда

```sh
cp .env.example .env
# обязательные значения в .env:
#   APP_ENV=prod
#   MAX_BOT_TOKEN=<токен>
#   BOT_MODE=live
#   BOT_WEBHOOK_PUBLIC_URL=https://<домен>/max/webhook
#   PUBLIC_BASE_URL=https://<домен>
#   EDGE_SITE_ADDRESS=<домен>
#   VITE_MOCK_BRIDGE=false
printf '%s' '<токен>' > /tmp/max_token
python3 scripts/derive_webapp_secret.py --token-file /tmp/max_token   # значение CORE_MAX_WEBAPP_SECRET_HEX
docker compose up -d --build
curl -fsS https://<домен>/api/v1/catalog -o /dev/null -w '%{http_code}\n'   # 401 без токена — норма
```

В кабинете MAX указать URL мини-приложения `https://<домен>/` и включить подписку на события
`bot_started`, `bot_stopped`, `dialog_removed`, `dialog_muted`, `dialog_unmuted`, `message_created`.

## 3. Порядок проверки внутри MAX (MAX-04)

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть чат с ботом, нажать «Старт» | приходит приветствие с кнопкой открытия приложения |
| 2 | Открыть мини-приложение кнопкой | первый экран за ≤ 3 с, без полосы «Имитация MAX» |
| 3 | Пройти онбординг | организация создана, предложены типовые документы |
| 4 | Добавить документ со сроком через 3 дня | карточка показывает «Скоро истекает», «осталось 3 дня» |
| 5 | Проверить ближайшее напоминание | в карточке дата и время в часовом поясе организации |
| 6 | Нажать системную кнопку «Назад» | возврат на предыдущий экран, на дашборде кнопка скрыта |
| 7 | Переключить системную тему | цвета меняются, текст остаётся читаемым, данные не теряются |
| 8 | Открыть форму, изменить поле и попытаться закрыть приложение | появляется подтверждение закрытия |
| 9 | Создать приглашение и нажать «Отправить в MAX» | открывается экран шеринга MAX с текстом и ссылкой |
| 10 | Открыть ссылку приглашения вторым аккаунтом | экран приглашения, после принятия — дашборд организации |
| 11 | В настройках нажать «Подготовить файл», затем «Скачать» | клиент MAX сохраняет файл `.ics` |
| 12 | Дождаться времени напоминания | в чате приходит сообщение с кнопкой, ведущей в карточку документа |
| 13 | Нажать кнопку в напоминании | приложение открывается сразу на карточке документа |
| 14 | Остановить бота в чате и открыть приложение | баннер «Напоминания не приходят» с кнопкой «Открыть чат с ботом» |
| 15 | Отключить сеть на телефоне и обновить экран | «Нет соединения» и кнопка «Повторить»; после включения сети данные загружаются |
| 16 | Закрыть и снова открыть приложение | состояние восстановлено, повторная авторизация не требуется |

Проверку повторить на iOS, Android, desktop и в веб-клиенте MAX (PLAT-08).

## 4. Что фиксировать по результатам

- версия клиента MAX и платформа (`WebApp.version`, `WebApp.platform`);
- фактические тела webhook (задача MAX-01) — сохранить обезличенные образцы
  в `services/bot/internal/adapters/webhook/testdata/`;
- поведение кнопки `open_app` (задача MAX-02);
- обнаруженные расхождения с `docs/max/max-platform-facts.md`.
