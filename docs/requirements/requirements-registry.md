# Реестр требований

Версия 1.0.0 · 20.09.2026 · владелец: Разработчик B

Источники: M-01 — запрос на проектирование, M-02 — кейс (PDF), M-05 — официальная документация MAX, ADR — принятое решение. Приоритет: Must — обязательно к 29.09; Should — обязательно, выполняется после Must по плану; Could — при наличии резерва. Критерии приёмки ссылаются на [стратегию тестирования](../testing/test-strategy.md) (T-*) и [сценарии приёмки](../testing/acceptance.md) (AC-*).

## Бизнес-требования

| ID | Источник | Требование | Приоритет | Критерий |
|---|---|---|---|---|
| BR-01 | M-02 | Решение относится к треку «Эффективный бизнес»; проблема сформулирована по формуле кейса | Must | формулировка в [product-brief](product-brief.md) и на слайде 2 презентации |
| BR-02 | M-02 | Польза: новый пользователь за ≤ 3 минуты получает реестр типовых документов со статусами сроков | Must | AC-02, замер времени на репетиции REL-02 |
| BR-03 | M-02 | Масштабируемость: новые виды деятельности, регионы, признаки и типы документов добавляются миграцией данных без изменения кода | Must | T-DOM-APPL; миграция с новым типом без изменения Go/TS |
| BR-04 | M-02 | Тестовые и модельные данные помечены явно | Must | бейдж «Модельные данные» в карточке, `data_status`, пометка «(тестовые данные)» в демо |
| BR-05 | пользователь, ADR-001 | Продукт — мини-приложение MAX: все пользовательские сценарии выполняются в его интерфейсе; бот только открывает мини-приложение и доставляет напоминания со ссылкой в него | Must | AC-01…AC-10 проходятся только через интерфейс мини-приложения; в боте нет команд, меняющих данные |
