# Стратегия тестирования

Версия 1.0.0 · 20.09.2026. Формат строки: поведение → данные → setup → ожидаемый результат → критерий pass/fail. Групповой идентификатор (например, `T-FE`) означает все тесты группы.

## 1. Уровни и инструменты

| Уровень | Инструменты | Где запускается | Кто |
|---|---|---|---|
| Модульные backend | `go test`, таблицы случаев | локально, `make test` | B (core), A (bot) |
| Интеграционные backend | `go test -tags integration`, профиль compose `test` (`postgres-test` на 127.0.0.1:55432) | `make test-integration` | B, A |
| Контрактные | kin-openapi (ответы против `openapi.yaml`), `buf lint`, `buf breaking` | `make verify-contracts` | B, A |
| Frontend | Vitest, Testing Library, MSW, jsdom | `npm test` | A |
| E2E | Playwright против локального compose с имитацией Bridge | `make e2e` | A |
| Ручные в MAX | протокол AC-MAX на 4 платформах | стенд | A |
| Нефункциональные | k6, `docker kill`, `measure_build.sh`, скрипты проверок | стенд или локально | B |

## Сценарий T-CONS-01: проверка семантики AC-05

1. Создать документ с датой окончания и отступами через публичный API core.
2. Зафиксировать `reminders_state` в ответе: ожидается `actual`.
3. Остановить reminders-service, изменить документ: ожидается `reminders_state=pending`, ответ 200.
4. Запустить reminders-service, дождаться доставки события: `GetSyncStatus` возвращает `in_sync=true`.
5. Повторно прочитать карточку: `next_reminder_at` пересчитан, `reminders_state=actual`.
6. Измерить задержку между шагами 3 и 5: предел 60 с, целевое значение p95 — 2 с.

Сценарий выполняется после реализации core-service; на текущем этапе проверены его составные части:
идемпотентный приём события, перестроение плана, ответ `GetSyncStatus`, а также вся цепочка
до доставки сообщения получателю (`docs/implementation/integration-report.md`).

## Запрещено

Ослаблять тест ради зелёного результата, удалять тест, обнаруживший реальную ошибку,
подтверждать запрос в двойнике без проверки содержимого, объявлять пройденной проверку,
которая фактически не выполнялась.
